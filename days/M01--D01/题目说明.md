# License CrackMe 01：本地卡密验证逆向练习

## 1. 挑战简介

这是一个用于学习软件逆向分析的入门练习程序。程序会要求输入一串卡密，并根据内部验证逻辑显示授权成功或授权失败。

本练习的目标是：**在不查看源代码的情况下，使用 IDA 分析程序的授权验证流程，并尝试让程序进入授权成功分支。**

- 难度：入门
- 目标架构：x86-64
- 文件格式：Linux ELF 64 位可执行文件
- 文件名：`1`
- 符号：已剥离（stripped）
- 运行环境：Linux x86-64；可使用 Kali Linux、Ubuntu 或 WSL
- 静态分析工具：IDA（可在 Windows 中运行）

> 注意：这是 Linux ELF 程序，不是 Windows `.exe`。Windows 版 IDA 可以分析它，但不能直接在 Windows 命令行中运行它。

## 3. 如何运行

将压缩包解压到 Kali / WSL 的目录中，然后进入程序所在目录：

```bash
cd /path/to/LicenseCrackMe01
```

赋予执行权限：

```bash
chmod +x ./1
```

运行程序：

```bash
./1
```

根据提示输入卡密。程序会反馈授权成功或授权失败。

如果出现 `Permission denied`，先检查是否执行了 `chmod +x`；如果出现 `No such file or directory`，请确认当前环境为 Linux x86-64，并检查程序解释器及运行环境是否完整。

## 4. 逆向分析任务

请按顺序完成以下任务，不必一开始就尝试修改程序：

### 任务一：识别文件

```bash
file ./1
```

确认它是 64 位 x86-64 ELF 文件。

### 任务二：查看可见字符串

```bash
strings -n 4 ./1
```

留意程序标题、输入提示、授权成功和授权失败等字符串。字符串只能提供线索，不能单独证明验证逻辑的位置或实现方式。

### 任务三：在 IDA 中定位关键代码

1. 使用 IDA 打开 `1`。
2. 等待自动分析完成。
3. 在 Strings 窗口中查找授权成功、授权失败和输入提示等字符串。
4. 查看这些字符串的交叉引用（Xrefs）。
5. 从引用位置向上追踪调用关系，寻找决定授权结果的判断逻辑。

### 任务四：理解验证逻辑

重点回答：

- 用户输入被保存在哪里？
- 输入在验证前是否经过处理？
- 程序比较了什么内容或计算结果？
- 哪条条件分支决定授权成功或失败？
- 验证函数的返回值或判断结果如何影响主流程？

### 任务五：完成挑战

选择一种方式验证你的分析：

- **方法 A：** 推导出程序接受的输入，并通过正常输入流程验证。
- **方法 B：** 在本地副本上修改相关控制流，使程序进入授权成功分支。

请保留原始文件，所有修改都在副本上进行。完成后，记录修改位置、修改前后的关键指令以及验证结果。

## 5. 建议提交的 Writeup

完成后，可以按下面的结构整理分析记录：
